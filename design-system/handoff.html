Handoff de desarrollo

De diseño a producción

Este documento contiene todo lo necesario para construir, extender y mantener el portal de Nueva Voz Colectiva Ecosystem sin tomar decisiones adicionales de diseño.

01 · Arquitectura del portal

El sitio es un portal institucional multi-página, no un one-page. Cada sección principal del sitemap es una página independiente con su propia URL, SEO, breadcrumb y CTA. La navegación nunca depende únicamente de anclas (#) — las anclas solo se usan dentro de una página para categorías internas (ej. Biblioteca).

  • Cada página real vive en su propia ruta: /programas/liderazgo-ciudadano.html
  • El header, mega-menú y footer son componentes compartidos (ver sección 06), no se duplican a mano
  • Todo módulo (Programas, Proyectos, Biblioteca, etc.) acepta páginas nuevas sin tocar las existentes

03 · Tokens y variables

Todas las variables viven en css/tokens.css. Nunca declarar un color, tipografía o espaciado fuera de ese archivo.

/* Color de marca (aprobado) */
--nvc-copper:  #B0783F;
--nvc-patina:  #5E8E7E;
--nvc-navy:    #16293F;

/* Tipografía */
--font-display: 'Archivo', system-ui, sans-serif;
--font-cond:    'Archivo Narrow', sans-serif;

/* Espaciado base 4px */
--sp-1: 4px;  --sp-5: 24px;  --sp-9: 96px;

04 · Grid y responsive

  • Ancho máximo de contenido: --maxw: 1240px, con padding lateral fluido --pad: clamp(22px,5vw,64px)
  • Grillas con .grid.g2 / .g3 / .g4 (CSS Grid + gap, nunca floats)
  • Breakpoints: móvil hasta 560px, tablet 561–980px, desktop 981–1439px, desktop grande ≥1440px
  • El header colapsa a menú hamburguesa + drawer por debajo de 980px

05 · Componentes

Documentación viva e interactiva de los ~25 componentes (botones, forms, cards, KPIs, tablas, modales, alertas, breadcrumb, paginación, buscador, filtros, tabs, acordeón, timeline, galería) en Design System → Componentes. Cada uno usa solo clases de components.css / base.css — no crear estilos inline nuevos para variantes ya cubiertas.

06 · Navegación / sitemap escalable

Header, mega-menú, footer y breadcrumb se generan desde un único arreglo SITE_MAP en js/nav.js. Para agregar una página al menú:

// Agregar una subpágina a Programas — no tocar nada más
children:[
  { label:'Nuevo programa', href:'programas/nuevo-programa.html', desc:'Descripción corta' },
]

Cada página declara su profundidad de carpeta con <body data-base="./"> (raíz) o data-base="../"> (una carpeta adentro) — todas las rutas del header/footer se resuelven contra ese valor.

07 · Estados e interacción

Todo componente interactivo define 5 estados como mínimo: default, hover, focus-visible, disabled, y success/error cuando aplica (ver base.css / components.css). El foco siempre usa outline: 2px solid var(--nvc-patina-deep) — nunca remover :focus-visible sin reemplazo accesible.

08 · Animaciones

  • Transiciones de UI: var(--dur-fast) (150ms) para hover/focus, var(--dur-med) (250ms) para paneles/drawers
  • Curva estándar: var(--ease) = cubic-bezier(.4,0,.2,1)
  • Sin loops decorativos infinitos en contenido de página — reservar animación para micro-interacción con propósito

09 · Convenciones y buenas prácticas

  • HTML canónico: cerrar cada etiqueta, comillas dobles en atributos, sin auto-cierre de elementos no-void
  • Nomenclatura de archivos: minúsculas, kebab-case, sin espacios ni acentos (desarrollo-territorial.html)
  • Contenido no confirmado se marca con el componente .placeholder-block + .placeholder-flag — nunca se inventan cifras, aliados o testimonios
  • El logotipo aprobado no se recolorea, deforma ni reconstruye — usar siempre assets/logo/nvc-logo-oficial.png como fuente única

10 · Cómo agregar una página nueva

  1. Duplicar la página existente más parecida en estructura (landing, detalle, o listado)
  2. Ajustar <title>, <meta name="description">, data-page y el data-trail del breadcrumb
  3. Agregar la entrada correspondiente al SITE_MAP en js/nav.js (una sola vez, se propaga a header/footer/mega-menú)
  4. Reutilizar únicamente componentes ya definidos en components.css
